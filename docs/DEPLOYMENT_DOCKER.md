# Установка PQTV на собственный сервер через Docker

## Требования

- Linux-сервер с установленными Docker Engine и Docker Compose v2.
- Доступ к серверу по SSH.
- Открытый порт для PQTV (по умолчанию 3000) либо настроенный reverse proxy.

## 1. Получить проект

```bash
git clone https://github.com/alexpikman/PQTV.git
cd PQTV
```

Для обновления уже установленной копии:

```bash
git pull --ff-only
```

## 2. Настроить секреты

```bash
cp .env.example .env
```

Откройте `.env` и обязательно задайте:
- `SESSION_SECRET` — длинный случайный секрет сессий;
- `APK_UPLOAD_TOKEN` — отдельный длинный случайный токен;
- `ADMIN_EMAIL` — адрес администратора;
- `ADMIN_PASSWORD_HASH` — bcrypt-хеш пароля администратора.

Сгенерировать два случайных секрета можно командами:

```bash
openssl rand -hex 32
openssl rand -hex 32
```

Сгенерировать bcrypt-хеш можно после установки зависимостей локально либо в контейнере сборки. Например, в каталоге проекта:

```bash
docker run --rm -v "$PWD":/app -w /app node:22-bookworm-slim sh -lc "npm install --no-save bcryptjs >/dev/null && node --input-type=module -e \"import bcrypt from 'bcryptjs'; console.log(bcrypt.hashSync('ЗАМЕНИТЕ_НА_СВОЙ_ПАРОЛЬ', 10))\""
```

Вставьте полученный хеш в `ADMIN_PASSWORD_HASH`. Не оставляйте демонстрационные значения.

## 3. Собрать и запустить

```bash
docker compose up -d --build
```

Проверить состояние:

```bash
docker compose ps
docker compose logs -f pqtv
```

Откройте в браузере:

```
http://SERVER_IP:3000
```

Если задан другой `PQTV_PORT`, используйте его.

## 4. Постоянное хранение

Compose создаёт два постоянных Docker volume:

- `pqtv_data` — состояние приложения, настройки, индексы, журналы и резервные копии;
- `pqtv_playlists` — файлы плейлистов.

Обычный перезапуск и пересборка контейнера не удаляют эти тома. **Не выполняйте `docker compose down -v`**, если не хотите удалить постоянные данные.

## 5. Обновление

```bash
git pull --ff-only
docker compose up -d --build
docker compose ps
```

Перед обновлением с важными данными рекомендуется сделать резервную копию томов.

## 6. Важно о режиме хранения

Этот Docker-набор обеспечивает размещение приложения и его файловых данных на вашем сервере. Он сам по себе не превращает текущие файловые модули в PostgreSQL и не переносит данные из Firestore.

Текущая кодовая база содержит клиентскую интеграцию Firestore и отдельные серверные файловые хранилища. До отдельной проверки и завершения адаптера хранилища нельзя считать, что все сущности PQTV работают исключительно на локальной базе или что облачная синхронизация отключена.

Не удаляйте исходный Firebase-проект и его данные после установки. Миграцию и переключение источника истины нужно выполнять отдельным проверяемым этапом.
